## 1. 范围

本文件只管理优化闭环最前端的因果模块：

```text
项目语义
  → 异构调度图
  → 诊断点 D
  → 责任点 R
  → 因果路径 P
  → 最小传播闭包 Ω
  → 反事实干预数据
  → CIP 学习模型
  → 接入在线控制器
```

后续 Agentic RL、条件生成器、局部搜索和完整调度优化不在本轮实施范围内。

## 3. 方法与代码来源边界

### 3.1 当前能够确认的工程事实

从当前仓库源码可以确认：

- `graph.py` 直接从本项目统一 IR 构造调度图；
- `cip.py` 在项目内实现诊断、责任点、路径、闭包和确定性排序；
- `counterfactuals.py`、`dataset.py` 在项目内定义反事实采集结构；
- `learning.py` 在项目内用 PyTorch 实现关系编码器和多任务头；
- 当前没有导入现成的“调度因果图/CIP”第三方实现；
- 当前没有放入仓库的外部算法源码副本。

这说明当前代码是项目内的独立工程实现，但不能据此声称基础方法全部原创，
也不能在没有提交历史和逐行溯源的情况下证明从未参考任何外部实现。

### 3.2 借鉴的通用方法思想

| 层级 | 通用研究基础 |
|---|---|
| 异构调度图 | disjunctive graph、resource/precedence graph、heterogeneous graph、message-passing GNN |
| 因果干预表达 | structural causal model、`do` intervention、counterfactual comparison |
| 诊断与责任点 | critical path/block、bottleneck analysis、root-cause localization |
| 最小闭包 | local neighborhood、dependency closure、partial schedule destroy/repair |
| 反事实对照 | matched controls、ablation、paired intervention experiments |
| 多任务 CIP 学习 | relational GNN、multi-task learning、pairwise ranking、sparsity regularization |

这些方法类别来自既有研究领域，不属于本项目首次提出。

### 3.3 当前项目自己的框架设计与组合

- 用统一调度 IR 支持 JSP、FSP、FJSP、HFSP 和项目约束调度；
- 将因果核心点统一表示为 \(h=(D,R,P,\Omega)\)；
- 在同一接口中表达诊断点、责任点、传播路径和最小闭包；
- 将规则基线、关系 GNN、局部修复和多保真 Oracle 串成可回退闭环；
- 要求学习模型提出的候选仍经过硬约束与 Full Oracle；
- 使用“同算子随机点、同点随机算子、同闭包规模随机区域”作为配对对照框架；
- 以证据门隔离 LLM 语义提案和已验证项目事实。

这些可以描述为“本项目的框架设计或工程组合”。在正式文献检索完成前，
不宣称为学术首创。

## 4. 从上到下的执行顺序

任何阶段没有通过完成门时，不提前把下一阶段标记为完成。

### C0：方法溯源与声明边界

**目标：**为异构图、因果干预、责任定位、闭包学习和反事实监督建立文献基线。

**Codex 负责：**

- 搜索并整理最接近的论文和开源实现；
- 建立“概念—论文—当前代码—差异”矩阵；
- 标记标准方法、工程组合和待验证创新。

**用户负责：**

- 确认项目目标是内部研发、开源、论文还是专利；
- 审核项目对外采用的原创性措辞；
- 对论文、模型和数据许可证做最终决定。

**完成门：**

- 参考文献和来源矩阵存在；
- README 不包含无法支撑的原创性表述；
- 关键代码没有许可证冲突。

### C1：四类问题的语义与数据契约

**目标：**为 JSP、FSP、FJSP、HFSP 各准备代表性实例及可靠语义。

**用户负责提供：**

1. 对应论文 PDF、补充材料和附录；
2. 论文对应的代码仓库和固定 commit；
3. 原始实例文件；
4. 数据格式说明；
5. 工件、工序、机器和模式的含义；
6. 全部硬约束；
7. 优化目标、优先级和容差；
8. 已知最优值、最好已知值或普通基线；
9. 数据、论文和代码许可证；
10. 可用的领域 Oracle、仿真器或验证结果。

**Codex 负责：**

- 从论文生成 `PaperSemantics`；
- 从代码生成 `CodeSemantics`；
- 输出 Paper→Code 对齐与冲突矩阵；
- 编写适配器并转换成统一 IR；
- 输出语义提案和 `unknown` 项；
- 构建确定性基线调度；
- 编写解析、约束和重放测试。

**用户验收：**

- 审核语义、约束和可修改变量；
- 对 `unknown` 给出确认或补充证据；
- 确认目标函数与业务一致。

**完成门：**

- 四类问题至少各有可解析实例；
- incumbent 可验证并能确定性重放；
- 硬约束、目标与可修改变量都有明确责任方。

### C2：异构图正确性验证

**目标：**证明图是调度实例的忠实表示，而不仅是可以构造。

**Codex 负责：**

- 对节点、边和数值特征编写 property-based 测试；
- 检查 precedence、resource sequence、eligibility 和 competition；
- 建立图到原调度的可追踪映射；
- 对四问题族分别输出图统计和可视化样例；
- 将规则假设边与数据验证边分开标记。

**用户负责：**

- 抽查图中的业务关系；
- 指出项目特有资源、全局汇聚资源和外生变量；
- 确认哪些关系可称为因果假设，哪些只能称为相关结构。

**完成门：**

- 图可以无歧义追溯到实例和 incumbent；
- 四类问题的结构测试通过；
- 不再把规则生成的边写成已识别因果边。

### C3：批量反事实采集

**目标：**从真实干预结果建立责任点、路径、闭包、收益、有效性和成本标签。

**Codex 负责：**

- 生成多质量 incumbent；
- 对同一诊断点执行多个责任点、算子和闭包等级；
- 自动执行三组配对因果对照；
- 记录 Full Oracle、失败类型、真实变化闭包和运行成本；
- 固定 seed、预算、求解器版本并支持断点恢复。

**用户负责：**

- 提供或运行高成本领域 Oracle；
- 对无法代码化的失败做业务判断；
- 确认 Oracle 版本和结果可作为正式标签；
- 决定算力、时间和 Token 预算。

**完成门：**

- 同一 incumbent 上存在配对干预与对照；
- 每个标签都能追溯到候选、Oracle 和日志；
- 训练、验证、测试按实例划分，避免数据泄漏。

### C4：CIP 模型训练

**目标：**训练 \(q_\phi(h\mid G,s)\)，预测收益、有效性、成本、风险、路径和闭包。

**Codex 负责：**

- 建立规则、MLP 和关系 GNN 基线；
- 运行多任务训练、早停和 checkpoint 保存；
- 评估排名、校准、闭包召回/精度、风险和收益误差；
- 运行 leave-one-family-out 和消融实验；
- 输出 dataset hash、配置、模型 hash 和指标。

**用户负责：**

- 确认训练资源和最大运行时间；
- 审核评价指标及业务权重；
- 决定模型大小和推理成本；
- 对跨问题族结论做最终验收。

**完成门：**

- 模型在未见实例上优于规则或 MLP 基线；
- 关键指标有置信区间；
- 结果可由固定配置重现。

### C5：接入主控制器

**目标：**用已训练 CIP 模型辅助或替换规则排序，同时保留安全回退。

**Codex 负责：**

- 实现 checkpoint 加载和版本校验；
- 将模型输出接入候选排序；
- 保留规则 fallback；
- 对 OOD、低置信度和模型失败自动回退；
- 保证所有候选仍通过完整约束和 Oracle。

**用户负责：**

- 审核回退阈值；
- 确认模型失效时采用的业务策略；
- 审核最终候选和实验结论。

**完成门：**

- 学习模型确实出现在默认调用链；
- 无 checkpoint 时系统仍可确定性运行；
- 学习模型不能绕过硬约束或 Full Oracle。

### C6：跨问题族验证与冻结

**目标：**验证因果核心点模块是否对多类调度问题具有稳定价值。

**Codex 负责：**

- 分问题族报告和 leave-one-family-out；
- 对比规则、MLP、GNN 和无因果对照；
- 执行 bootstrap、配对检验、效应量和多重比较校正；
- 记录失败问题族和适用边界。

**用户负责：**

- 审核实例是否具有代表性；
- 确认是否允许公开数据与结果；
- 决定是否达到发布、论文或继续研发标准。

**完成门：**

- 不用单一平均数掩盖失败问题族；
- 每项泛化结论都有未见实例证据；
- 失败边界写入正式文档。

1. 更新本文件的状态和证据；
2. 更新 `SYSTEM_ARCHITECTURE.md`；
3. 数学状态变化时更新 `FORMULA_IMPLEMENTATION_MATRIX.md`；
4. 实际实验结果写入 `EXPERIMENTS.md`；

6. 不以“代码存在”替代“训练完成”或“实验有效”。
