## 不可删减的研究结构

1. 从稳定 incumbent 改进，而非默认从零求解。
2. 统一因果骨架 A→L→W→T→D→J。
3. 未知项目的完整语义编译必须使用 LLM 多轮理解；程序索引、代码、测试和文档
   证据负责约束与核验，人工负责隐含业务规则的最终审核。
4. CIP 必须同时含诊断点、责任点、因果路径和传播闭包。
5. 关键点发现需支持规则召回与可学习异构图/MLP 排序。
6. 监督头至少覆盖改善、有效性、成本、闭包、路径、风险和排序。
7. 使用反事实候选与 pairwise 标签，而非只训练成功样本。
8. 闭包使用节点级 membership，并对无必要大闭包施加稀疏惩罚。
9. Agent 使用 3–10 步短时程控制，不直接替代排程求解器。
10. 动作为算子、闭包等级、控制动作的联合选择，并执行合法性 Mask。
11. 先 BC，再离线策略学习，最后受控在线 PPO。
12. 生成器每轮重新编码部分排程，支持多候选与 solver fallback。
13. 闭包外保持固定；失败时扩张、换点或回退。
14. Code、Static、Light、Full 四级验证逐级增加成本。
15. 多保真模型校正轻量代理对完整 Oracle 的偏差。
16. 使用同算子随机点、同点随机算子、同闭包规模随机区域作因果对照。
17. 日志保存语义、incumbent、CIP、动作、各级验证、结果和失败原因。
18. 实验覆盖 JSP、FSP、FJSP、HFSP，按实例划分防止泄漏。
19. 比较随机、solver-only、VNS、ALNS、CIP、Agentic 与完整方法。
20. 做语义、路径、闭包、RL、多保真和因果对照消融。
21. 报告效果、有效率、成本、Oracle 次数、排名和闭包质量。
22. 使用配对统计、置信区间、效应量和多重检验校正。
23. 保留 LGS 等可选扩展，但不让其阻塞第一版主链。
24. 不宣称全局最优；只声明在给定预算和 Oracle 下验证过的严格改善。

逐项代码位置与研究状态见 [TRACEABILITY.md](../../cross_module/TRACEABILITY.md)。
