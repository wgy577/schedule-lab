# L2D 代码语义识别多模型对比报告

> 实验日期：`2026-07-24`  
> 案例：NeurIPS 2020 L2D / JSSP  
> 比较对象：GLM-5.2、DeepSeek-v4-pro、MiMo-v2.5、Kimi-k3、
> Claude-Opus-4.8  
> 标签状态：`draft_llm_label`，尚未人工确认  
> **解释状态：历史工程基线；不得作为真实能力排名或当前最高推理协议结果**

## 1. 结论

在本次单案例、固定 draft 隐藏标签的历史代码盲测中：

1. **Claude-Opus-4.8 是当前最均衡的默认选择**：Macro-F1 为 `0.628`，
   18/18 证据通过，总 Token 最少，仅需 80.36 秒且一次完成。
2. **Kimi-k3 单次语义分数最高**：Macro-F1 为 `0.653`，证据全部通过；但成功
   运行耗时 453.05 秒、发生一次 Schema 修复，前一次正式运行还因网络读取超时
   失败，而且接口强制 `temperature=1`。它更适合作为高质量复核模型，不适合
   当前直接作为低延迟、确定性主模型。
3. **MiMo-v2.5 最快**：27.07 秒完成，但证据通过率只有 `0.529`。它可以用于
   低成本候选召回，不能在没有 Critic/证据修复的情况下直接生成正式语义。
4. **DeepSeek-v4-pro 速度稳定，引用较可靠**，但本例 Macro-F1 只有 `0.478`，
   对问题族、决策和允许干预的分类偏差较大。
5. **GLM-5.2 基线识别稳定但较慢**：Macro-F1 `0.615`、证据全部通过，代码侧
   耗时 209.48 秒。它仍可作为第二意见，但综合成本不如 Opus。

这不是正式模型排行榜。当前只有一个 JSSP 案例，而且隐藏标签本身由 GLM-5.2
生成、尚未人工审核。进一步审查还发现，旧 Schema 会把若干语义等价表达当成错误，
并把论文问题定义、代码运行事实、实验 baseline 和经验性主张混在同一标签中。
因此报告现在只保留为旧 Harness 的可复现工程基线。

本表中的 MiMo 是历史 `mimo-v2.5` 运行，不代表当前已切换的
`mimo-v2.5-pro`；所有旧运行也不代表当前“最高质量推理”配置。新一轮正式比较必须
等待人工标签完成，避免用错误标尺继续提分。人工核验入口见
[L2D_PAPER_CODE_HUMAN_VERIFICATION.md](L2D_PAPER_CODE_HUMAN_VERIFICATION.md)。

## 2. 公平性设置

所有模型共享：

- 同一篇论文生成的**固定隐藏标签**；
- 同一官方代码仓库 commit：
  `7b2efbb1ffc960260b16952f2bed68e500765bf0`；
- 同一代码字符上限：42,000；
- 同一选项库、Pydantic Schema 和证据审计器；
- 同一 `paper/` 排除规则；
- 同一八类集合评分；
- 顺序运行，避免并发限流影响延迟。

每个模型只执行：

```text
代码 inventory
  → LLM 选择读取文件
  → 白名单证据包
  → LLM 结构化语义识别
  → 程序证据核验
  → 与固定隐藏标签比较
```

GLM-5.2 的表中成本只统计其代码读取规划与代码分析，不包含它此前生成论文标签
的 22,650 Token 和 116.60 秒。

## 3. 总体结果

| 模型 | Macro-F1 | Exact rate | 证据通过率 | Token | 成功运行耗时 | Schema 修复 |
|---|---:|---:|---:|---:|---:|---:|
| **Kimi-k3** | **0.653** | 0.250 | **1.000** | 41,011 | 453.05 秒 | 1 |
| **Claude-Opus-4.8** | **0.628** | **0.375** | **1.000** | **15,225** | **80.36 秒** | 0 |
| GLM-5.2 | 0.615 | **0.375** | **1.000** | 24,571 | 209.48 秒 | 0 |
| MiMo-v2.5 | 0.576 | **0.375** | 0.529 | 20,124 | **27.07 秒** | 0 |
| DeepSeek-v4-pro | 0.478 | 0.250 | 0.909 | 25,128 | 80.97 秒 | 0 |

“成功运行耗时”是规划与分析阶段返回结果中记录的 API 延迟之和，不包含本地
inventory 和 JSON 写盘时间。

可辅助观察一个非正式指标：

```text
evidence-adjusted score = Macro-F1 × evidence pass rate
```

| 模型 | Evidence-adjusted score |
|---|---:|
| Kimi-k3 | 0.653 |
| Claude-Opus-4.8 | 0.628 |
| GLM-5.2 | 0.615 |
| DeepSeek-v4-pro | 0.434 |
| MiMo-v2.5 | 0.305 |

该乘积不是论文指标，只用于防止“分类分数尚可但引用大量失效”的模型被误判为
可直接使用。

## 4. 分语义组结果

| 模型 | 项目类型 | 问题族 | 环境 | 目标 | 约束 | 决策 | Oracle | 允许干预 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| GLM-5.2 | 0.000 | 1.000 | 1.000 | 1.000 | 0.750 | 0.500 | 0.000 | 0.667 |
| DeepSeek-v4-pro | 1.000 | 0.000 | 0.750 | 1.000 | 0.571 | 0.000 | 0.500 | 0.000 |
| MiMo-v2.5 | 1.000 | 1.000 | 0.750 | 1.000 | 0.857 | 0.000 | 0.000 | 0.000 |
| Kimi-k3 | 0.000 | 1.000 | 0.800 | 1.000 | 0.857 | 0.500 | 0.400 | 0.667 |
| Claude-Opus-4.8 | 1.000 | 1.000 | 0.667 | 1.000 | 0.857 | 0.500 | 0.000 | 0.000 |

共同规律：

- 五个模型都正确识别 makespan 最小化目标；
- 除 DeepSeek 外，其余模型都正确识别 JSSP；
- “项目类型”在 `scheduling_optimization` 与 `mixed` 之间存在口径分歧；
- 决策与 Oracle 是当前选项库最不稳定的两组；
- 这说明下一步应先改善标签定义和选择题边界，而不是马上训练小模型。

| 模型 | 输入 Token | 输出 Token | 规划耗时 | 分析耗时 | Provider 尝试 |
|---|---:|---:|---:|---:|---:|
| GLM-5.2 | 18,907 | 5,664 | 17.87 秒 | 191.61 秒 | 2 |
| DeepSeek-v4-pro | 20,332 | 4,796 | 26.19 秒 | 54.78 秒 | 1 |
| MiMo-v2.5 | 17,887 | 2,237 | 5.39 秒 | 21.68 秒 | 1 |
| Kimi-k3 | 25,616 | 15,395 | 37.52 秒 | 415.53 秒 | 2 |
| Claude-Opus-4.8 | 12,753 | 2,472 | 18.21 秒 | 62.15 秒 | 1 |

额外稳定性记录：

- Kimi-k3 第一次正式运行在代码分析网络读取阶段超时，没有生成完整 Artifact；
- Provider 当时没有捕获底层 socket 超时，该缺口现已修复并有回归测试；
- Kimi-k3 第二次成功，但发生一次 Schema 修复；
- Kimi-k3 网关只允许 `temperature=1`，其他模型使用 `temperature=0`；
- Kimi 第一次失败调用没有返回 usage，因此其额外 Token 无法可靠统计；
- Opus 经中转站返回的模型标识为 `claude-opus-4-8`。系统只能审计网关返回值，
  无法独立证明中转站背后的真实权重版本。

## 6. 证据质量

- GLM、Kimi、Opus：分别有 30/30、30/30、18/18 条引用通过；
- DeepSeek：1 条引用把表达式当成 symbol，证据通过率 0.909；
- MiMo：8 条引用把属性或变量当成可索引 symbol，证据通过率 0.529。

这不意味着通过的解释必然正确，只意味着引用确实指向本次白名单证据包内存在的
文件与符号。

## 7. 推荐的模型 Harness

以下组合是旧 draft 标签下的历史建议，当前暂停作为生产路由依据：

```text
MiMo-v2.5（历史运行；当前配置已改为 mimo-v2.5-pro）
  → 快速读取规划或低成本候选召回

Claude-Opus-4.8
  → 主语义编译器

Kimi-k3
  → 仅在关键语义冲突、低置信度或人工要求时做高成本复核

程序 Evidence Auditor
  → 淘汰不存在的文件和 symbol

人工审核
  → 确认项目类型、决策、Oracle 和隐含业务约束
```

GLM-5.2 和 DeepSeek-v4-pro 暂作为第二意见与消融基线保留。正式采用路由前，至少
还需要：

1. 按人工核验清单分别确认 PaperClaims、ImplementationTruth 和 alignment；
2. 加入 FJSP、FSP/HFSP、RCPSP 等网上公开案例；
3. 每个模型每案例重复运行，尤其是 temperature=1 的 Kimi；
4. 报告均值、方差、失败率和费用；
5. 对“项目类型、决策、Oracle”重新设计层级化选择题；
6. 为每阶段增加 checkpoint，避免后段失败后重复支付规划成本。
