## 1. 为什么先暂停评分结论

上一轮多模型实验使用同一份 `draft_llm_label` 做了可复现的工程比较，但该标签由
LLM 根据论文生成，尚未经过人工确认。它只能回答“模型输出与这份 draft 标签有多
一致”，不能回答：

- 论文是否完整、准确地描述了代码；
- 代码是否真的实现了论文中的全部约束与实验；
- 某个模型是否已经找全代码中的约束；
- 哪个模型对真实项目语义最准确。

已经发现三类会扭曲旧分数的问题：

1. **等价表达被当成错误**：`JSP/JSSP`、单机 `capacity=1` 与
   `no_overlap`、选择工序与诱导机器序列在当前 Schema 中可能被分开计分。
2. **不同事实层被混在一起**：论文问题定义、代码运行语义、实验基准和作者的性能
   主张不应放进同一个集合标签。
3. **“论文没有写”不等于“代码没有做”**：代码可能含实现细节；反过来，论文中的
   release time、基线或实验设置也不一定进入主运行链。

因此，在下面的人工核验完成前：

- 旧 Macro-F1 与 exact rate 保留为历史工程基线；
- 不把旧分数解释成模型真实能力排名；
- 不用旧分数决定训练标签；
- 不根据论文单方面覆盖 CodeSemantics。

### 1.1 2026-07-25 用户确认的解释口径

- L2D 研究对象按最普通的静态 JSSP 理解，不应为经典约束重复投入大量语义推理；
- 论文公式中的 release time 在此案例对应所有作业从 0 可用，不作为当前优化杠杆；
- OR-Tools、传统 PDR、benchmark 和训练硬件属于实验比较，不属于调度程序核心约束；
- 策略先选择工序，环境再放入最早可行位置，是经典构造式调度惯例；
- 后续重点不是“枚举所有会进入时间公式的量”，而是识别能区分候选、能被决策利用、
  会影响优化方向和局部传播的因素。

该口径已经进入
`SCHEDULING_SEMANTIC_KNOWLEDGE_AND_IMPACT.md` 和约束影响 Critic。它不等于全局声明
release time 永远无影响；在动态到达、非零释放时间或延期目标项目中必须重新评估。

## 9. 对旧多模型结果的重新解释

在人工裁决前，不应直接判定模型遗漏了所有约束，也不应直接认定某模型已经找全。
至少存在以下评分歧义：

| 旧字段 | 可能的合理答案 | Harness 应如何改 |
|---|---|---|
| `project_type` | `scheduling_optimization` 或 `mixed` | 拆成业务任务类型与实现技术类型 |
| `problem_family` | `JSP` / `JSSP` | 建立规范化同义词 |
| `constraints` | `capacity=1` / `no_overlap` | 建立层级与等价关系 |
| `decisions` | `select` / `sequence` / 派生 `start_time` | 区分直接动作、诱导决策、环境派生量 |
| `oracles` | 环境转移、构造器、validator、实验 baseline、Full Oracle | 拆成五类角色 |
| `resource_eligibility` | 固定机器数据或硬约束 | 允许“数据编码的约束”来源 |

所以旧报告中的单项低 F1 可能同时包含：

- 模型真实遗漏；
- 标签遗漏；
- 等价表达未归一化；
- 事实层混淆；
- 论文与代码真实不一致。

在这些来源被人工拆开之前，不进行新一轮“提分式 Prompt 调参”。

## 10. 人工审核完成后才实施的 Harness 改造

### 10.1 三层真值

后续标签应至少拆成：

```text
ProblemTruth
  数学问题、环境、目标、硬约束

ImplementationTruth
  代码实际支持的输入、状态、动作、转移、验证、实验路径

PaperClaims
  作者在论文中陈述的问题、方法、实验设置和经验性结论
```

三者通过 `paper_and_code / paper_only / code_only /
representation_equivalent / conflict / ambiguous` 对齐，不再强行合并成一个集合。

### 10.2 分离评分

计划分别报告：

1. CodeSemantics 对人工确认的 ImplementationTruth 的 recall/F1；
2. PaperSemantics 对人工确认的 PaperClaims 的 recall/F1；
3. 论文—代码 alignment 分类准确率；
4. 证据定位准确率；
5. unknown/conflict 校准；
6. 规范化前和语义等价归一化后的两套分数。

`ambiguous` 和 `unverified` 不作为 false；经验性主张不进入硬约束完整率。

### 10.3 人工批准门

只有当本文件中的关键条目完成审核后，才允许：

- 生成 `human_verified_label`；
- 重跑多模型正式比较；
- 根据比较结果选择主模型、Critic 和路由；
- 用这些标签训练或蒸馏 code-only 模型；
- 将分数写成模型能力结论。
